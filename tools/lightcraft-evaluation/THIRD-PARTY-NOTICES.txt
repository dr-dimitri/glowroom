The LC-03 developer-only CPU reference adapts the following source algorithms
from the pinned Lightcraft source. PicEdit selects the upstream MIT license
option for these portions. The complete upstream MIT license and NOTICE are
preserved verbatim in licenses/lightcraft/LICENSE-MIT and
licenses/lightcraft/NOTICE. The upstream NOTICE describes the entire upstream
product; the separate upstream materials it lists are not imported by this
evaluation.

crates/pipeline/src/local.rs:
  log_lum; guided, guided_coeffs, guided_apply, guided_fast,
  guided_fast_step; median_hv, median_row, transpose; base_detail_radius,
  tone_base_detail, tone_base; BASE_DETAIL, BASE_DETAIL_MAX, BASE_EPS;
  base sigma selection from plane_sigmas.
crates/pipeline/src/finish.rs:
  The local highlights/shadows weights and RGB exp2(delta) application in
  finish_with. No complete finish pipeline or global ToneMap is imported.
crates/raster/src/blur.rs:
  box_radii, radii_for, box_row, box_v and gaussian (three-box approximation
  with clamped edges).
crates/raster/src/resample.rs:
  weights, resize, Filter and Pixel behavior for Box downsampling and bilinear
  coefficient upsampling used by guided_fast. The optional oracle extracts the
  original module without tests (also compiling support/eval, madd, fit and half,
  but calling only Box/Bilinear resize); the Swift adapter implements these two
  filters.
crates/pipeline/src/tests_tone.rs and tests_local.rs:
  Median, fine-line, guided-filter, constant-field and edge fixture concepts.

Modifications in PicEdit (2026): Swift/array adaptation; bounded execution and
cancellation through the existing developer harness; explicit developed-pixel
extended-linear-sRGB contract with an explicit RGB bridge into Rec.2020 before
its original luminance weights are used; scalar gain applied to original sRGB
(commuting with the linear bridge); explicit native/image-space scale;
coverage-weighted median, means and resampling for independent alpha handling;
and isolated tone-stage evaluation without Lightcraft's RAW development, global
tone model, contrast/whites/blacks, color, sharpening or denoising pipeline.
Details, numerical validation and limitations are documented in
../../docs/LIGHTCRAFT-TONE-EVALUATION.md. Upstream extracted oracle functions
remain temporary build inputs; their input-file hashes and frozen results are
recorded beside the oracle.

No upstream photographs, fonts, branding, camera matrices, neural model code,
weights or other assets are transferred. No Rust dependency is added to the
application or its normal build/test path.

LC-04 adds the following developer-only adaptations at the same pinned commit:
crates/pipeline/src/local.rs:
  CLARITY_EPS and the clarity/texture sigma selection from plane_sigmas;
  log_lum, guided_fast and the shared Gaussian/resampling functions above.
crates/pipeline/src/finish.rs:
  The clarity detail clamp, midtone weight, texture detail clamp and tame weight,
  smooth, and RGB exp2(delta) application. With only clarity active, the tone
  base is log_l, matching local::prepare's fallback.
crates/color/src/lib.rs and crates/pipeline/src/tone.rs:
  LUMA_2020, luminance_2020 and GREY for the independent numeric oracle.

LC-04 uses the common bounded Swift filters and adds coverage-normalized Gaussian
convolution for alpha. Same-radius Gaussian clarity, unclamped log texture and
the existing PicEdit gamma-domain texture formula are explicitly PicEdit
ablations, not original Lightcraft algorithms. Strength is separate from
immutable prepared planes. Upstream original bodies and unchanged finish
statements are temporary oracle inputs only; hashes and results are preserved
in lc04-reference-oracle. See ../../docs/LIGHTCRAFT-DETAIL-EVALUATION.md.

LC-05 adds the following developer-only adaptations at the same pinned commit:
crates/pipeline/src/colorops.rs:
  The chroma-only saturation/vibrance fast path in ColorOps::apply, wrap and
  oklch_hue_of_srgb_hue(25) for the positive-vibrance hue heuristic. No mixer,
  Point Color, B&W, grading, calibration or local colour adjustment is enabled.
crates/color/src/perceptual.rs:
  The original OkLab matrices/transforms (signed cbrt and cubing), and the HSV /
  OkLCh helpers used only by the independent oracle to derive the skin hue.
crates/color/src/lib.rs:
  Mat3, Xy, RgbSpace, primary/white definitions and Bradford support, compiled
  only as temporary oracle inputs. Their arithmetic is unchanged; serde derive
  attributes are omitted. Swift retains the existing explicit sRGB/Rec.2020
  colour bridge and stores the original generated Float32 OkLab matrices.
crates/color/src/transfer.rs:
  srgb_to_linear in the oracle's fixed sRGB-hue conversion.
crates/pipeline/src/finish.rs and output.rs:
  gamut_map_to as an explicit optional SDR-sRGB output policy (peak=1), with
  OutputSpace::Srgb's [0.2126, 0.7152, 0.0722] luminance weights. The full finish,
  global tone, proofing and output-encoding pipelines are not imported.

LC-05 preserves signed/extended RGB in the raw diagnostic policy and separately
evaluates the targeted ColorOps plus destination-gamut-map combination. Both
policies keep exact zero/zero identity. The upstream approximate gray-axis
residual remains visible, including at saturation=-100; there is no undisclosed
gray correction or negative-LMS clamp. The Swift implementation fuses per-pixel
colour conversion and adjustment through the common bounded LC-03 row pool,
handles straight alpha separately and adds no rendering cache or dependency.
Original-function oracle inputs/hashes and frozen numeric results are recorded
in lc05-reference-oracle. See ../../docs/LIGHTCRAFT-COLOR-EVALUATION.md.

LC-06 adds the following developer-only adaptations at the same pinned commit:
crates/pipeline/src/local.rs:
  detail_scale, nr_radius, nr_params, NrLum, NrColor, NR_MIN_SIGMA,
  NR_MIN_BLEND, apply_nr and log_lum; full guided, guided_coeffs and
  guided_apply (not guided_fast). Only luminance or chroma NR is active per
  adapter. The fixed unexposed nr_detail, nr_color_detail and
  nr_color_smoothness controls are 50; nr_contrast is not implemented.
crates/raster/src/blur.rs:
  box_sigma for the variance-based subpixel radius fade, with the shared
  original Gaussian functions listed above. The original modules are temporary
  oracle inputs only; Swift reuses the bounded LC-03 Gaussian/row workers.
crates/color/src/lib.rs and crates/pipeline/src/tone.rs:
  LUMA_2020, luminance_2020 and GREY for the original-function oracle.

LC-06 keeps the explicit extended-linear-sRGB/Rec.2020 bridge, signed input,
original luminance floors, and chroma's final nonnegative Rec.2020 clamp.
Negative luminance can yield large positive chroma outputs because the source
uses a positive divisor floor but multiplies by the original signed Y; this
limitation is preserved and independently recorded, not silently corrected.
It adds normalized alpha coverage to every spatial mean and keeps hidden RGB
zero; the original source is opaque RGB only. Exact zero and the original
subpixel no-op bypass colour conversion. Native scale uses full-image geometry,
never crop dimensions. Epsilon follows scale squared only for explicitly known
area-averaged inputs; unknown sampling retains native epsilon. The unscaled
ablation uses native radius/epsilon/blend. No RAW decoder, learned model,
production rendering change or persistent cache is introduced. Original Rust
functions, source hashes and 40 frozen cases are recorded in
lc06-reference-oracle. See ../../docs/LIGHTCRAFT-DENOISE-EVALUATION.md.
