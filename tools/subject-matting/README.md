# Local subject matting model

PicEdit runs this model natively with Core ML. Python is a developer-only conversion dependency. Photographs never leave the machine. The app's automatic-mask settings import the resulting package after provenance, interface and integrity checks.

## Prepare

On an Apple Silicon Mac with Python 3.11 and a macOS 14+ SDK:

```sh
python3.11 -m venv /tmp/picedit-subject-env
/tmp/picedit-subject-env/bin/python -m pip install -r tools/subject-matting/requirements.txt
/tmp/picedit-subject-env/bin/python tools/subject-matting/check_deform.py
/tmp/picedit-subject-env/bin/python tools/subject-matting/prepare.py \
  --source /tmp/picedit-subject-sources --download \
  --output /tmp/PicEditBiRefNetHR.mlpackage
```

The download is approximately 444 MB. Preparation traces on the CPU with at most eight threads because torchvision's deformable convolution has no MPS implementation. Preparation and the dependent Core ML conversion stay ordered; running them simultaneously would duplicate substantial model memory. The source and three SHA-256 values are pinned in `prepare.py`. Previously downloaded sources can be used without `--download`. A checksum mismatch fails before executing model source. No `trust_remote_code`, pickle deserialization, runtime Python or runtime network model loader is used.

Import `PicEditBiRefNetHR.mlpackage` through PicEdit's local subject-matting setup. Model generation can require considerably more memory than app inference. Keep the sibling `.inventory.json` with qualification records; it identifies exact generated bytes. The converter canonicalizes package UUIDs and protobuf map serialization for reproducibility with the pinned tool versions.

Qualify it against the original PyTorch graph using an already developed, local sRGB image:

```sh
/tmp/picedit-subject-env/bin/python tools/subject-matting/qualify.py \
  --source /tmp/picedit-subject-sources --model /tmp/PicEditBiRefNetHR.mlpackage \
  --image /path/to/local-developed-photo.png --output /tmp/picedit-subject-qualification
```

This saves native/reference alpha masks, diagnostic −5 EV background renders and numeric differences. It performs one cold and one warm native prediction. Reference and native process peaks are reported separately; native Python memory includes conversion libraries and the compiler, so it must not be presented as PicEdit's inference-only memory usage. The image does not leave the machine.

Reference inference runs in a child process and exits before native model loading, so PyTorch's retained CPU allocator does not overlap with Core ML's model allocation. `--reference-only` can stop after saving the reference if the native measurement will use the standalone Swift tool.

For a standalone native process measurement, compile `benchmark.swift` with `swiftc`. Pass the same developed image, `gpu` or `cpu`, and a new output directory. Prefer an already compiled `.mlmodelc` to keep compiler memory out of this process. Its input resize matches PicEdit's CoreGraphics high-quality resize, which can differ slightly from the PyTorch/Pillow bilinear resize. It saves native Float32 alpha plus timings and peak process RSS; system GPU/driver allocations are not fully represented by that RSS value.

```sh
swiftc tools/subject-matting/benchmark.swift -o /tmp/picedit-subject-benchmark
/tmp/picedit-subject-benchmark /tmp/PicEditBiRefNetHR.mlpackage compile /tmp/PicEditBiRefNetHR.mlmodelc
/tmp/picedit-subject-benchmark /tmp/PicEditBiRefNetHR.mlmodelc /path/to/photo.png gpu /tmp/picedit-subject-gpu
/tmp/picedit-subject-benchmark /tmp/PicEditBiRefNetHR.mlmodelc /path/to/photo.png cpu /tmp/picedit-subject-cpu
/tmp/picedit-subject-env/bin/python tools/subject-matting/compare_native.py \
  --reference /tmp/picedit-subject-qualification/reference-alpha.npy --native /tmp/picedit-subject-gpu
python3 -m unittest discover -s tools/subject-matting -p 'test_*.py'
```

For exact graph parity, pass the `reference-input.png` saved by `--reference-only` to the Swift tool. This removes differences between Pillow and CoreGraphics resizing. The Swift tool saves `alpha-1.f32` and `alpha-2.f32` in row-major Float32 layout; the comparison gates every prediction, including the first. Non-finite values, invalid alpha ranges or shapes fail closed. Run CPU and GPU benchmarks sequentially because they share the machine's memory and compute budget.

`--side 1024` on both preparation and reference qualification exports an exploratory speed/quality candidate using the identical HR-trained weights. It does not change the app's approved 2048 model contract; lower-resolution fine-edge quality must be judged separately before accepting it.

Measured on one developed RAW preview on an M2 Pro with 16 GiB RAM, the approved 2048 model took about 6.7 s to load plus 41.0 s for its first GPU prediction and 33.5 s for a repeated prediction with weights retained. CPU inference took 8.7 s after a 6.3 s load but differed more from the Float32 reference. An exploratory 1024 export took 6.4 s to load, 3.2 s for the first GPU prediction and 0.7 s for the repeated prediction; its wider soft needle edges were visibly worse. These figures describe the inspected workload and do not establish a general speedup or Lightroom equivalence. See `qualification.json` for numerical differences and memory limits. In the app, retaining a finished mask avoids repeating inference without retaining model weights.

## Contract

- Model: `ZhengPeng7/BiRefNet_HR-matting`, pinned revision `5d6b6f8adcb5b417c871b1d84ceaae9871355b7f`, MIT.
- Input: `image`, RGB image 2048 × 2048, sRGB, aspect stretched to the square. Core ML scales bytes by 1/255; graph subtracts ImageNet mean `[0.485,0.456,0.406]` and divides by standard deviation `[0.229,0.224,0.225]` per channel.
- Output: `alpha`, Float32 multi-array `[1,1,2048,2048]`, sigmoid foreground coverage. Restore original aspect ratio, then invert for a background mask. Preserve fractional coverage; do not threshold or erode it.
- Native compute policy: CPU + GPU. The model retains a CPU execution path. ANE is excluded because the upstream Core ML investigation observed excessive compilation time for this architecture.
- Real learned deformable convolution offsets and modulation are preserved through bilinear sampling plus 1 × 1 convolutions. `check_deform.py` checks nonzero offsets, out-of-image samples and masks against torchvision before full model qualification.
- `common::fuse_transpose_matmul` is disabled to preserve attention behavior on Apple GPU drivers. Numeric comparison of the full native model against the pinned PyTorch reference is still required for release qualification.
